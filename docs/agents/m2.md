# M2 Context Manager (integrator)

Two build agents ran in parallel worktrees: `feat/context-m2` (new `services/context`, see `context.md`) and `feat/geometry-m2` (DFM, CAD import, mass, see `geometry.md`). Both were reviewed against `AGENTS.md` and merged. The integration below joins them in the agent loop and the CLI.

## Integration

- `services/agent/project_context.py`: `Grounding(pack, rules, process)`. The prompt gets the retrieved facts with ids to cite, team conventions, the project rules (stated as checked automatically) and, when one exists, a similar earlier design as a starting point or an uploaded part's size and holes. Facts that come from a rule's source line are not repeated as facts.
- Facts become requirement checks: hole callouts (thread callouts use the ISO 273 range), toleranced bores, and size chains. A parameter whose provenance names a fact id gets that fact's document provenance (ref + quote).
- The project's rules for the chosen process go to `geometry.build`; static violations become repair problems with their suggested fix.
- CLI: `partwright context add <project> <files…>`, `partwright context show <project>`, and `--project/--process` on `generate` and `refine`. Successful generations are recorded in the project graph with their shape descriptor, so they come back as similar parts.

## Loop changes found while running the demo

- Unused parameters are dropped before validation (they caused repair churn; requirement checks already catch forgotten dimensions).
- Repairs are a fresh prompt quoting the previous design and its problems, not a growing chat; the 4B echoed its last assistant turn otherwise. Temperature rises to 0.9 when an answer repeats.
- New checks with concrete messages: overlapping holes (with both centres), holes outside the outline (with the valid coordinate range), hole-to-edge suggestions with the valid centre range.
- Fixed: `parallel_*` edge sets included cylinder seams, so vertical fillets failed on plates with holes; console output now UTF-8 on Windows.

## Demo (`evals/demos/m2`)

```bash
uv run partwright context add m2demo evals/demos/m2/sensor-plate-requirements.pdf evals/demos/m2/plate-design-rules.md evals/demos/m2/previous-sensor-plate.step
uv run partwright generate "Sensor mounting plate per the project requirements" --project m2demo --process milling_3axis --out out/m2-sensor-plate
```

Result on `qwen3.5:4b`, 2026-10-25: 5/5 spec checks after 5 repairs (113 s). Attempt 1 overlapped the bore and the mounting holes; attempts 2–4 violated the project rule "hole-to-edge ≥ 2 x D" (caught by the DFM check); attempt 5 shrank the holes below the M6 clearance (caught by the spec requirement); attempt 6 passed. Every dimension cites its PDF line (`p1:l2`, `p1:l4`), the M6 clearance cites ISO 273. The graph grew from 28 to 63 relations; a later query ranks the generated plate first as a similar part with its full design, and `stale()` on REQ-1 returns that model.

## Regression check on the M1 set (`evals/results/m1-20261025-234808`)

5/10 cases fully correct, 21/35 checks, 20 repairs, median 63 s, against 6/10, 24/35, 23 repairs, 84 s before the M2 loop changes (`m1-20261025-225624-noplan`). The one case lost is the DN50 flange: the model drew the disc on XZ and drilled along Z, which the new outline check rejects correctly but with a misleading range; the message now names the drill direction and says the plane is probably wrong. With n = 10 a one-case swing is within run-to-run noise; the M3 eval set must grow towards the planned 50 cases before small changes can be judged.
