# CAD backends

Researched 2026-10-25. "Verified" means it was run on the dev machine (Windows 11, Python 3.11.9, uv 0.9.13) in a throwaway venv in the scratch area. The venv was deleted afterwards.

## TL;DR

- **Kernel library: build123d 0.13.0** on OCP 8.0.1 (OCCT 8.0.1), using the `cadquery-ocp-novtk` wheel. It installs headless on Windows in about 10 s from cache, and the venv is 544 MB. Licence Apache-2.0.
- **Do not install CadQuery 2.8.0 in the same environment.** It pins `cadquery-ocp<8` and pulls in VTK (venv 1.1 GB). uv resolved the two together by downgrading CadQuery to 2.7.0 and installing two OCP wheels on top of each other, and then `import cadquery` failed (verified). Pick one kernel library per environment.
- STEP carries no feature history. "Opens in CAD like a designer-built tree" needs a native replay format next to the STEP. The plan is STEP AP214/AP242 for geometry, names and colours, plus our IR as the parametric source of truth, plus an optional FreeCAD `.FCStd` with a real PartDesign tree generated by headless FreeCAD.

## What "opens in CAD like a designer-built feature tree" can realistically mean

STEP (AP203/214/242) transfers B-rep geometry, the assembly product structure, names, colours, layers and, in AP242, PMI and some construction history (ISO 10303-108/111 parametrics are almost unsupported by CAD importers). Every mainstream CAD tool imports STEP as **dumb solids** with no feature tree.

| Option | What the designer gets | Offline | Effort | Recommendation |
|---|---|---|---|---|
| STEP AP214/AP242 with names, colours, hierarchy | Correct parts and assembly structure, editable only by direct modelling (push/pull) | yes | done (verified) | **Always ship** |
| Our IR (`.json`) + generated build123d `.py` | A full parametric source: parameters, units, provenance and constraints, regenerated deterministically | yes | core product | **Always ship**. This is the true parametric model |
| FreeCAD `.FCStd` with a real tree (PartDesign Body → Sketch with Sketcher constraints → Pad/Pocket/Fillet; Spreadsheet for parameters; Assembly joints) | A genuine editable feature tree in a free CAD tool | yes (needs FreeCAD installed, ~1 GB) | medium: an IR → FreeCAD Python emitter run under `FreeCADCmd`; FCStd is a zip of `Document.xml` plus BREP files, but it must be produced by FreeCAD to be valid | **Phase 2, optional plugin** (LGPL, so subprocess only) |
| Onshape FeatureScript or REST API replay | A native Onshape tree | **no** (cloud) | medium | Later and opt-in only |
| Fusion 360 Python script / SolidWorks VBA/C# macro that replays features | A native tree after running the script in the user's CAD | yes | medium per target, and it cannot be tested in CI without a licence | Later; community plugins |
| SolveSpace `.slvs` | A constraint-driven model | yes | low–medium | Skip (GPL-3 library) |

Consequences for the IR:

- Model features the way a designer does: sketch on a named plane/face reference, fully constrained sketch, extrude/revolve/cut with an explicit extent, then dress-up features. Do not just emit CSG of primitives. That keeps FreeCAD/Fusion emitters a 1:1 mapping.
- Keep sketch constraints in the IR and solve them ourselves with **planegcs** (Python bindings of FreeCAD's PlaneGCS, LGPL-2.1+, v0.9.6 2026-10-10, win_amd64 wheels for **cp312+ only**, [PyPI](https://pypi.org/project/planegcs/)). Feed the solved geometry to build123d. Avoid `python-solvespace`/`py-slvs` (GPL-3).
- Persist stable feature IDs and face references by name (build123d `label`, or topology-naming tags), not by face index.

## Pinning (backend env)

```
python = "3.12"            # planegcs wheels are cp312+; build123d supports 3.11–3.14
build123d==0.13.0          # -> cadquery-ocp-novtk 8.0.1.1.0, ocpsvg 0.7.0, ocp-gordon 0.3.1
bd_warehouse==0.4.0        # Apache-2.0 standard parts (see dfm-and-standards.md)
planegcs==0.9.6            # LGPL-2.1+, dynamic import only
# CadQuery 2.8.0 only in a separate env if ever needed (cadquery-ocp 7.9.3.1.1 + vtk 9.6.2)
```

## Risks

- OCP 8.0 is new (Aug–Sep 2026), and OCP 8.0.1.1 was a regression-fix release. Pin exact versions and run golden-geometry tests on upgrade.
- OCCT can segfault or hang on bad booleans or fillets. Run CAD compilation in a subprocess with a timeout (see `async-jobs-and-stack.md`).
- FreeCAD headless: some workbench modules need `sys.path` tweaks ([wiki](https://wiki.freecad.org/Headless_FreeCAD)). It is a large install on tight disk, so keep it optional.
