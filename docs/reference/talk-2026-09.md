## Write-up summary (S17)
- Line drawn between impressive 3D demos and usable mechanical design: parametric B-rep models with feature trees, constraints and mates that survive simulation and manufacturing.
- Two macro problems: tool fragmentation and manual work inside each tool.
- Inputs: sizing-tool results, requirements, specifications, existing CAD, mission definitions. Kyrall is not building a requirements or sizing product.
- "More circular" design: change a calculation or requirement → CAD geometry and simulation update; simulation flows back.
- Downstream bar: topology-optimisation STL back to parametric CAD; manufacturing-method changes reshape geometry automatically.
- Three use cases in delivery: conceptual design (thousands of early configurations from sizing XML); asset generation (drawing or photo → parametric part with feature tree); STL → parametric CAD (simulation, scan, legacy).
- Adoption blockers in order: models that run locally on ordinary machines; fine-tunes on company CAD/design habits; reliability via automatic evals; deep integration into existing tools.
- Legacy CAD plus design intent (why the part looks that way) matters more than training another model.
- Short quote: "A usable model is not any 3D mesh."

## Items for the parity checklist
Mission definitions and sizing XML as inputs; circular change propagation; B-rep + constrained sketches + mates + feature tree; Onshape export; STL/TO/scan → parametric; drawing/photo → part (≤1 min, ~90 %); BWB parts < 5 min each; thousands of variants; knowledge base → "model ready context" with tolerances; local small model on a laptop; same-input-same-output; automatic evals of input coverage; CAX/PLM integration; DfM checks and manufacturing-driven geometry edits.
